# FundScope V8 数据采集架构

## 目标

V8 把采集流程拆成三类任务，避免所有数据都使用逐基金、逐证券串行请求。

### 1. 批量源

适合一次请求获取大表的数据：

- 基金代码 `fund_name_em`
- 基金经理 `fund_manager_em`
- A 股实时估值与市值 `stock_zh_a_spot_em`
- 市场级基金报告

这类任务不通过堆高线程数提速。

### 2. 中等粒度并发

适合按季度或行业板块拆分：

- 市场报告：2–4 路
- 行业映射：按东方财富行业板块并发获取成份股

行业映射从“逐证券查询行业”改成“按行业板块批量映射”，请求数量从数千级降到行业板块数量级。

### 3. 高粒度按需并发

适合必须逐对象获取的数据：

- 基金年度持仓
- 基金成立日期补充
- Security Master 成长指标深度补齐
- Return Gap 所需行情

支持 4 / 8 / 12 路，并使用自适应限速。

## 默认研究池

V8 的基金研究和持仓采集默认只保留主动偏股产品：

- 股票型
- 混合型
- 明确属于主动股票投资的 QDII

默认排除：

- 货币
- 债券、纯债、二级债、可转债
- 指数、ETF、联接、被动产品
- FOF、养老目标、REIT、商品

所有原始基金份额仍保存在 `fund_share_classes`，只是退出默认研究池。

## Fund Master

A / C / E、前端 / 后端收费等共享底层组合的份额归入同一 Fund Master，只选择一个代表份额采集持仓。

## 时间范围

持仓任务支持：

- 最近 1 / 2 / 3 / 5 年
- 自定义年份范围
- 成立至今

“成立至今”优先读取本地 `fund_profiles.inception_date`。缺失时才通过 AKShare `fund_overview_em` 补充成立日期，并写入缓存。成立日期无法确认时不会猜测起始年份，该基金会记录为 unresolved 并跳过。

## 增量逻辑

主键仍以基金代码、报告期、证券代码为核心。

采集前检查：

- Fund Master 是否已有其他份额的同一报告期数据
- 当前年份已披露到哪个季度
- 本地已有季度是否完整

默认只请求缺失年度 / 缺失报告期。强制刷新需要显式选择。

## 披露口径

V8 为持仓新增：

- `report_type`
- `disclosure_scope`

默认映射：

- Q1 / Q3：季度报告，top10
- Q2：中期报告，full
- Q4：年度报告，full

“退出披露”继续保留披露语义，不解释为确认清仓。

## Security Master

快速主表：

1. `stock_zh_a_spot_em` 一次获取市值、PE、PB
2. `stock_board_industry_name_em` 获取行业板块
3. 并发调用 `stock_board_industry_cons_em`，按行业板块批量映射证券

深度补齐：

- 在快速主表基础上，再逐证券补营业收入和利润增长指标

因此日常更新优先使用快速主表，研究需要时再做深度补齐。

## 日常维护

“增量更新”按顺序执行：

1. 基金代码
2. 基金经理
3. Fund Master
4. 最近市场报告
5. 当年缺失持仓
6. 快速 Security Master

代码升级不迁移数据库位置。V8 继续使用：

Windows: `C:\Users\<用户名>\.fundscope\fundscope.db`

macOS / Linux: `~/.fundscope/fundscope.db`

## V8.1 采集策略更新

V8.0 中统一的 4 / 8 / 12 路模式已在 V8.1 调整为按数据源分配并发。基金持仓接口更容易触发东方财富频率限制，因此使用 2 / 4 / 6 路；Security Master 继续使用更高并发。具体配置以 `backend/app/collection_policy.py` 为唯一维护入口。

所有长任务还应遵守 `docs/TASK_ENGINE_V8_1.md` 中的暂停、取消和限频冷却约定。
